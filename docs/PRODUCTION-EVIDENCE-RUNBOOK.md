# OMNIX Production Evidence Runbook

This is the canonical operator path for producing real-machine release evidence.

A green hosted CI run is necessary but is not production acceptance. Production approval still requires real desktop Office, restart persistence, offline local AI, live provider, lifecycle, consumer-security, and trusted production-signing evidence for one exact release candidate.

## Non-negotiable identity rule

Real-machine reports must not be created by calling the raw Office/provider/offline/restart harnesses directly.

Use `tools/bound-real-acceptance.ps1` for these evidence classes:

- `FullOfficeE2E`
- `LocalOffline`
- `Provider`
- `RestartBefore`
- `RestartAfter`

The bound runner validates the installed `OMNIX-build-identity.json` before it adds `EvidenceBinding`. The identity must match:

- the exact source commit under test;
- the installed `OMNIX.Core.dll` SHA-256;
- the installed `OMNIX.Excel.dll` SHA-256;
- the installed `OMNIX.Word.dll` SHA-256;
- the installed `OMNIX.PowerPoint.dll` SHA-256.

The binding also records the SHA-256 of `OMNIX-build-identity.json`. The final production guard requires all bound reports to agree on that payload identity, source commit and Core hash and rejects stale evidence.

Lifecycle evidence uses the same verified installed build identity. Its Baseline and AfterRepair phases validate all four primary assemblies and require the same `SourceCommit`, `CoreSha256` and `PayloadIdentitySha256`; the final AfterUninstall report carries that verified binding after the application payload has intentionally been removed.

The lower-level scripts such as `real-office-acceptance.ps1`, `full-office-e2e.ps1`, `provider-acceptance.ps1`, `local-offline-acceptance.ps1`, and `reboot-persistence-acceptance.ps1` are implementation harnesses. A raw PASS from one of them is not production evidence by itself.

## 1. Freeze the release candidate

Use one exact source checkout and one exact installer file for the complete acceptance cycle.

```powershell
$installer = 'C:\path\to\OMNIX-Setup.exe'
$sourceCommit = (git rev-parse HEAD).Trim().ToLowerInvariant()
$installerSha = (Get-FileHash -Algorithm SHA256 -LiteralPath $installer).Hash.ToLowerInvariant()

$sourceCommit
$installerSha
```

Do not continue if `git status --porcelain` contains unreviewed release-affecting changes.

If a source ZIP is used instead of a Git checkout, its root must contain a valid `SOURCE-COMMIT.txt` produced from the exact release source.

## 2. Sign before exact-installer acceptance

Production Authenticode signing changes the outer `.exe` hash. Therefore, when a production certificate is available, sign the final installer before producing exact-installer real-machine evidence.

```powershell
.\build\sign-production.ps1 `
  -InstallerPath $installer `
  -CertificateThumbprint '<trusted-code-signing-thumbprint>' `
  -TimestampUrl 'https://<trusted-rfc3161-timestamp-service>'

$installerSha = (Get-FileHash -Algorithm SHA256 -LiteralPath $installer).Hash.ToLowerInvariant()
```

Never reuse lifecycle, Office E2E, consumer-security, or other installer-bound evidence produced for the unsigned/development installer as production evidence for the signed installer.

The signing helper does not create, export, download, or store a private key. Production approval still requires the final gate to verify a valid trusted timestamped signature.

## 3. Install the exact candidate normally

Close Excel, Word and PowerPoint. Run the exact candidate through the normal supported installation path. Do not disable Office security, Defender, SmartScreen, Trust Center, or organizational policy.

After installation, confirm that `%LOCALAPPDATA%\Programs\OMNIX\OMNIX-build-identity.json` exists. Do not edit it.

## 4. Run bound Full Office E2E

Run from the exact source checkout that corresponds to the installer payload:

```powershell
.\tools\bound-real-acceptance.ps1 `
  -Kind FullOfficeE2E `
  -InstallerPath $installer `
  -ExpectedInstallerSha256 $installerSha `
  -SourceCommit $sourceCommit
```

This canonical invocation produces/binds the real Office E2E report and the subordinate persistence/UI/task-pane reports generated by the full Office harness.

A successful bound report must carry binding schema 2 or newer, the exact source commit, the installed Core hash, the installed payload identity hash, and `PrimaryAssembliesValidated=true`.

## 5. Run live provider evidence

Use a real configured provider/account/model. Provider availability, quota and pricing are account/provider dependent.

```powershell
.\tools\bound-real-acceptance.ps1 `
  -Kind Provider `
  -SourceCommit $sourceCommit `
  -TimeoutSeconds 45
```

Do not place API keys, full prompts or full model responses into release evidence.

## 6. Run offline local-AI evidence

This test is valid only when public Internet is actually observed disconnected and a real local Ollama or LM Studio model completes the request. The harness must not disable networking/firewall state for the test.

```powershell
.\tools\bound-real-acceptance.ps1 `
  -Kind LocalOffline `
  -SourceCommit $sourceCommit `
  -TimeoutSeconds 45
```

## 7. Run restart persistence in two phases

Before the normal user-initiated Windows restart:

```powershell
.\tools\bound-real-acceptance.ps1 `
  -Kind RestartBefore `
  -SourceCommit $sourceCommit
```

Restart Windows normally yourself. The acceptance script must not trigger or bypass the restart.

After signing back into the same Windows user and before replacing/updating OMNIX:

```powershell
.\tools\bound-real-acceptance.ps1 `
  -Kind RestartAfter `
  -SourceCommit $sourceCommit
```

`RestartAfter` rejects a changed source commit, changed installed Core, changed installed payload identity, or unchanged Windows boot session.

## 8. Run payload-bound lifecycle evidence

Lifecycle acceptance is a separate exact-installer-bound and installed-payload-bound three-phase test. Close all Office applications for every phase.

First save real OMNIX settings so `settings.dat` exists, then capture the installed baseline:

```powershell
.\tools\lifecycle-acceptance.ps1 `
  -Phase Baseline `
  -InstallerPath $installer `
  -SourceCommit $sourceCommit
```

Baseline validates `OMNIX-build-identity.json` against the exact source checkout and hashes the installed Core, Excel, Word and PowerPoint assemblies before it saves lifecycle state. It stores an `EvidenceBinding` with binding schema 2 or newer.

Run the exact same installer normally as a repair. Then:

```powershell
.\tools\lifecycle-acceptance.ps1 `
  -Phase AfterRepair `
  -SourceCommit $sourceCommit
```

AfterRepair revalidates the installed build identity and all four primary assemblies. It fails if the source commit, Core hash or `PayloadIdentitySha256` changed, even if the outer installer filename is unchanged. The repair phase must record `PayloadIdentityPreservedAcrossRepair=true` and prove primary-assembly validation after repair.

Uninstall OMNIX through its normal uninstall path. Preserve evidence/logs until the test is complete. Then:

```powershell
.\tools\lifecycle-acceptance.ps1 `
  -Phase AfterUninstall `
  -SourceCommit $sourceCommit
```

AfterUninstall cannot hash an application payload that should no longer exist. Instead, it requires a previously passing Baseline + AfterRepair identity chain and carries the verified Baseline `EvidenceBinding` into the final lifecycle report. The final production guard cross-checks that binding against Office E2E, provider, offline and restart evidence.

The lifecycle result must therefore prove all of the following for the same release candidate:

- exact installer SHA-256 binding;
- exact source commit binding;
- the same installed `OMNIX-build-identity.json` before and after repair;
- validation of Core + Excel + Word + PowerPoint primary assemblies before and after repair;
- exact settings preservation across repair;
- no modification of the shared Office recovery subtrees OMNIX promises not to alter;
- healthy registration and maintenance-task behavior after repair;
- complete OMNIX-owned cleanup after uninstall while preserving user data when requested.

## 9. Run consumer security evidence

Use a normal protected consumer Windows machine. Microsoft Defender real-time protection and behavior monitoring must remain enabled. Observe SmartScreen through the normal UI; do not bypass/disable it for the test.

Example when normal installer launch is not blocked:

```powershell
.\tools\consumer-security-acceptance.ps1 `
  -InstallerPath $installer `
  -SmartScreenDisposition NotBlocked
```

If SmartScreen presents a warning and the publisher/hash is reviewed before using the normal allowed UI path, use `WarnedButAllowed`. Use `Blocked` when it blocks the candidate. `NotTested` is a failure state.

Hosted-runner Defender scans where real-time protection is off are CI diagnostics only and do not satisfy this consumer-machine gate.

## 10. Run deterministic privacy evidence

The final gate also requires the deterministic compiled Gateway privacy report. Use the Core built from the exact source candidate and retain the resulting report at the path supplied to the final gate.

Do not substitute UI-only privacy observations for the compiled Gateway test.

## 11. Run the final production gate

Only after all evidence above belongs to the same intended production candidate:

```powershell
.\tools\final-production-gate.ps1 `
  -InstallerPath $installer
```

The final gate is fail-closed. It checks exact installer binding, source/build/payload identity binding, freshness, Office task-pane evidence, payload-bound lifecycle repair evidence, consumer security, offline/local AI, live provider, privacy evidence, and trusted timestamped Authenticode requirements.

The only production PASS is:

```json
{
  "TestId": "OMNIX-FINAL-PRODUCTION-GATE-002",
  "FailureCount": 0,
  "OverallPass": true
}
```

Anything else is not production approval.

## Evidence freshness and replay resistance

Current final binding policy rejects:

- Office E2E/persistence/UI/restart evidence older than 168 hours;
- lifecycle evidence older than 168 hours;
- provider/offline evidence older than 72 hours;
- consumer-security evidence older than 72 hours;
- timestamps implausibly in the future;
- missing/old binding schema;
- mismatched source commit;
- mismatched installed Core hash;
- mismatched installed payload identity hash;
- lifecycle evidence that did not preserve payload identity across same-build repair;
- lifecycle evidence that did not validate all four primary assemblies before and after repair;
- different installer hashes for installer-bound reports.

Regenerate evidence after any source change, rebuild, re-signing, installer change, installed primary-assembly change, or payload identity change.

## Development previews are not production evidence

A GitHub development preview may have exact-head CI provenance, a source ZIP, runtime-hardening evidence and a checksum-bound installer while still being explicitly `DEVELOPMENT_ONLY` and `ProductionReleaseApproved=false`.

That is expected. Hosted CI cannot replace real interactive Excel/Word/PowerPoint, a genuine reboot, consumer SmartScreen/Defender state, live account/provider behavior, offline local-model operation, or trusted production Authenticode acceptance.
